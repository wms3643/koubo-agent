# PostgreSQL 数据模型设计草案

本文件描述将本地口播剪辑项目扩展为多用户服务时的数据模型。对应 DDL 见 [schema_postgres.sql](schema_postgres.sql)。该方案尚未接入应用：当前 LangGraph 检查点使用 SQLite，素材和产物保存在本地项目目录。SQL 文件是设计参考，不代表已经完成迁移、部署或性能验证。

## 设计目标

多用户场景需要处理项目归属、剪辑决策版本、渲染任务幂等与运行状态恢复。草案以 `projects` 为业务聚合根，将逐字稿、剪辑方案、字幕、任务及质检报告关联到项目。视频与渲染文件计划存放于对象存储，数据库只保存对象键、校验值、媒体元数据和状态。

## 数据域

| 数据域 | 主要表 | 目的 |
| --- | --- | --- |
| 账号与项目 | `users`、`projects` | 项目归属、软删除、并发更新控制 |
| 素材 | `media_assets` | 登记源视频、音频与渲染文件的元数据 |
| 转写 | `transcripts`、`transcript_segments`、`text_corrections` | 保存版本、时间戳和人工修正 |
| 剪辑与字幕 | `cut_plans`、`cut_plan_ranges`、`timeline_maps`、`subtitle_cues` | 保存删留决策、时间映射及字幕版本 |
| 代理运行 | `agent_runs`、`agent_steps`、`approvals`、`agent_checkpoints` | 记录运行、审批和恢复状态 |
| 渲染与质检 | `render_jobs`、`artifacts`、`qc_reports` | 跟踪任务、产物和质量检查 |
| 审计 | `audit_logs` | 记录重要业务操作 |

## 关键约束

- 逐字稿、剪辑方案和字幕采用独立版本，允许修正文本而不覆盖历史方案。`is_current` 的唯一性由部分索引约束。
- 剪辑区间以毫秒整数保存，可使用 PostgreSQL 范围类型与 GiST 约束阻止同一方案中的冲突区间。
- `timeline_maps` 保存剪前到剪后的时间映射；字幕与动效据此对齐，区间长度和顺序应在写入时校验。
- `render_jobs.idempotency_key` 用于识别重复提交。数据库唯一约束只能阻止重复登记；外部付费调用还需稳定的任务标识、提交状态持久化与恢复逻辑，才能避免重复扣费。
- 金额使用以分为单位的整数；媒体时间使用毫秒整数，减少跨组件换算歧义。
- `agent_checkpoints` 使用 JSONB 保存可演进的状态，但需要规划结构版本、保留周期和迁移策略。

## 存储与访问

草案将结构化数据保存在 PostgreSQL，大文件保存在兼容 S3 的对象存储中。对象存储直传、分片续传、冷热分层和 CDN 分发属于后续服务化能力，当前 Web 服务尚未实现。保存 `object_key` 不能自动提供访问控制；上线前还需落实租户鉴权、下载授权与对象生命周期管理。

## 落地工作

1. 校验 DDL 与现有项目文件、LangGraph 状态之间的字段映射，建立迁移与回滚方案。
2. 接入认证与项目级授权，并为所有项目数据访问建立隔离测试。
3. 接入对象存储、上传完成确认、文件校验和清理策略。
4. 实现渲染任务的持久化状态机及外部调用幂等，验证失败与重试场景。
5. 选择与当前 LangGraph 版本兼容的 PostgreSQL 检查点实现，完成恢复测试。

在上述工作完成前，本文件只作为后续扩展的设计依据。
