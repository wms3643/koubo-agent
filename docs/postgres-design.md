# 数据库架构与实施规范

本文记录 PostgreSQL 运行存储，并规定业务数据模型、事务边界和验收要求。运行存储通过 `python -m langgraph_app.database init` 初始化；账号、素材版本和渲染台账的业务表定义见 [schema_postgres.sql](schema_postgres.sql)，用于业务存储层扩展。两组表各自维护，运行初始化命令只负责检查点和会话表。连接与部署步骤见 [部署与运行](deployment.md)。

## 运行存储

`DATABASE_URL` 启用 PostgreSQL 后端。标准图和对话主管复用同一组连接接口，分别由官方 `PostgresSaver` 将原生检查点写入 `koubo_pipeline` 和 `koubo_chat`。会话标题、项目绑定及界面事件保存在 `koubo_app.conversation_snapshots.payload` 中，数据库以 JSONB 原子更新整个工作区快照。

连接使用自动提交、字典行格式、连接超时和 SQL 超时。初始化命令持有咨询锁，运行表 DDL 在事务内执行，Saver 表由官方迁移维护。服务启动与健康检查核对运行表和迁移版本；数据库错误不会触发后端切换。

Web 层串行持久化会话快照，进程重启后从数据库重建会话列表；模型上下文从独立检查点恢复。删除会话时清理对应的模型检查点，包括服务重启后尚未创建主管对象的会话。快照不保存付费授权和正在执行的线程对象。

## 业务数据模型

业务存储层按以下模型组织项目归属、剪辑版本、代理执行记录、审批、任务与产物索引。视频、音频、透明动效层和成片由文件存储承载，业务表保存定位信息、SHA-256 和媒体元数据。LangGraph 检查点由兼容当前框架版本的 Saver 管理，与业务运行摘要分别维护。

| 数据域 | 表 | 职责 |
| --- | --- | --- |
| 账号与项目 | `users`、`projects` | 项目归属、状态、软删除与并发更新 |
| 素材 | `media_assets` | 文件位置、校验值、大小、时长与画面规格 |
| 转写 | `transcripts`、`transcript_segments`、`text_corrections` | 逐字稿版本、时间戳与人工修正记录 |
| 剪辑与字幕 | `cut_plans`、`cut_plan_ranges`、`timeline_maps`、`subtitle_cues` | 剪辑决策、双时间轴和字幕版本 |
| 代理运行 | `agent_runs`、`agent_steps`、`approvals` | 执行状态、节点结果、回退来源与人工决定 |
| 状态归档 | `agent_checkpoints` | 可查询的业务状态快照 |
| 渲染与质检 | `render_jobs`、`artifacts`、`qc_reports` | 任务状态、输出登记与检查明细 |
| 审计 | `audit_logs` | 关键操作的执行人、时间和变更内容 |

## 数据约束

时间统一使用毫秒整数，金额统一使用分。时间区间采用左闭右开形式 `[start_ms, end_ms)`。输入校验拒绝负时间、结束时间不大于开始时间、超出素材时长以及非法状态转换。

`projects` 是业务聚合根。接口先从认证上下文获得用户身份，再按项目归属查询数据；不得信任请求体中的 `owner_id`。对子表的读写也必须通过所属项目验证权限。现有单列外键保证引用存在；服务化迁移应补充复合外键或等效约束，保证素材、转写、方案和输出属于同一项目。

DDL 中的剪辑排斥约束阻止同一方案、同一动作的区间重叠。审批方案前还须检查保留区间与删除区间互斥、时间范围有效且映射连续。`timeline_maps` 规定原区间与目标区间长度相等；写入时应额外验证目标区间从零开始、按顺序衔接。

字幕的 `is_current` 标记属于整条轨道。切换版本时应在同一事务内更新该方案的全部字幕条目，并验证当前条目只来自一个版本。若需要数据库直接约束唯一当前轨道，应增加字幕轨道主表，将当前版本标记移到主表中。

## 版本与事务

逐字稿、剪辑方案与字幕分别编号，已审批或被任务引用的版本保持不可变。修订生成新版本，下游任务绑定明确的版本号和输入校验值。

创建新逐字稿或剪辑方案时，先锁定对应的 `projects` 行，再分配版本号、取消旧版本的 `is_current`、插入新版本及其明细。部分唯一索引约束每个项目只有一个当前版本；事务失败时整体回滚。

剪辑审批在一个事务中完成方案状态更新、审批记录与审计记录。提交前校验审批所针对的版本仍然有效，重复审批不得重复启动任务。使用 `row_version` 进行项目更新时，应采用比较并交换：

```sql
UPDATE projects
SET current_stage = 'subs', row_version = row_version + 1
WHERE id = :project_id AND owner_id = :owner_id
  AND row_version = :expected_version AND deleted_at IS NULL;
```

影响行数为零时返回版本冲突，重新读取项目后再决定是否重试。数据库事务内不执行模型调用、视频编码或对象上传，避免长时间持锁。

## 任务提交与恢复

任务幂等键由项目、输入版本、文件校验值、规范化任务规格和处理器版本共同生成。相同键重复提交返回已有任务；修改字幕、剪辑方案或渲染参数后生成新键。唯一约束防止重复登记，外部服务调用仍需单独的幂等策略。

任务状态按以下规则推进：

```text
queued → running → succeeded
                 → failed
queued → cancelled
failed → queued（允许重试且未超过上限）
```

Worker 在短事务中用 `FOR UPDATE SKIP LOCKED` 领取任务并更新状态，事务提交后执行处理。生产调度需要通过版本化迁移为 `render_jobs` 增加 `worker_id`、`lease_until` 和 `heartbeat_at`；只有租约持有者可以确认任务完成。租约过期后先核对外部任务状态，再决定重新领取。

外部生成服务的提交标识必须持久化。请求超时但提交结果不明时，不直接重发：优先按稳定请求标识查询服务端任务；服务不支持查询或幂等提交时，将任务转交人工核对。取消任务也需确认外部执行状态，不能只修改本地状态。

文件先上传到临时位置，校验大小、SHA-256 与媒体规格后登记 `media_assets`。任务成功确认与 `artifacts` 登记在同一数据库事务中完成。存储与数据库没有共同事务，残留临时文件由定期清理任务处理，不能将尚未校验的文件公开为成片。

## 检查点与人工恢复

LangGraph 的原生检查点包含通道版本、待处理写入与序列化数据。业务表 `agent_checkpoints.state` 保存状态摘要，不能直接替代框架检查点。服务化接入应使用官方 PostgreSQL Saver，并与业务表分开维护迁移和保留策略。

运行记录中的 `thread_id` 需要支持框架使用的字符串标识；现有 DDL 使用 UUID，接入前应迁移为 TEXT，或明确实现 UUID 与框架标识的映射。标准流程与对话会话采用不同标识命名空间，避免状态相互覆盖。

审批请求绑定运行、检查点和目标操作。恢复前核对项目权限、运行状态与检查点版本；过期审批返回冲突。故障恢复应同时读取框架检查点和任务台账，已成功的外部任务通过产物校验后复用。

## 部署与迁移

数据库使用独立业务 schema。迁移账号具有建表和扩展权限，应用账号仅具有运行所需的读写权限。远程连接校验证书，密码通过部署环境或密钥管理系统提供，日志不得记录完整连接串。

实施时由存储适配层读取以下配置；它们是服务化配置约定：

| 配置 | 用途 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL 连接地址 |
| `DB_POOL_MIN`、`DB_POOL_MAX` | 连接池容量 |
| `DB_STATEMENT_TIMEOUT_MS` | SQL 执行超时 |
| `STORAGE_BACKEND` | 本地文件或兼容 S3 的对象存储 |
| `STORAGE_BUCKET` | 对象存储桶 |
| `CHECKPOINT_RETENTION_DAYS` | 已完成运行的检查点保留周期 |

初始化 DDL 在空业务 schema 内执行一次，后续变更使用有编号、可追踪的迁移。部署流程依次执行备份、迁移、应用启动、健康检查与恢复验证。DDL 含 `pg_trgm` 和 `btree_gist`，部署账号需具备安装扩展的权限。

迁移采用先扩展、再切换、后清理的方式：新增字段和索引，回填数据，验证新旧读取结果，再切换应用。破坏性变更在回滚窗口结束后执行。SQLite 检查点迁移需使用对应 Saver 的读写接口验证状态与恢复行为，不直接复制底层表。

备份同时覆盖业务库、原生检查点和媒体对象清单。数据库恢复至指定时间点后，按对象版本与校验值核对产物；恢复目标时间和最大容许数据损失由部署环境确定，并通过恢复演练验收。

## 验收要求

| 场景 | 验收结果 |
| --- | --- |
| 空库初始化与重复部署 | 首次迁移成功；已应用迁移不会重复执行 |
| 并发切换方案版本 | 仅一个当前版本；失败事务不留下部分明细 |
| 越权访问与跨项目引用 | 读取、更新、审批和产物下载均被拒绝 |
| 重复提交任务 | 返回同一任务，不重复登记或调用外部付费服务 |
| Worker 崩溃或网络超时 | 可核对执行状态并恢复，不盲目重发 |
| 审批后重启 | 从相同检查点恢复；重复或过期审批被拒绝 |
| 上传成功但登记失败 | 文件不作为完成产物展示，残留对象可清理 |
| 数据库与对象恢复 | 项目版本、运行状态和媒体校验值一致 |

验收记录应注明应用提交、迁移版本、PostgreSQL 与 Saver 版本、测试输入和实际结果，作为发布依据。
